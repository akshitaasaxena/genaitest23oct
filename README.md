# Orient BlackSwan History Catalogue Assistant

A Retrieval-Augmented Generation (RAG) system that answers questions about the **Orient BlackSwan History Catalogue 2024–25** using only the content of the PDF itself. If an answer isn't present in the document, the system replies **Not found** rather than guessing — every answer that is given is cited with the page number(s) it came from.

Built for **Project 4 of the GenAI mid-term: Orient BlackSwan History Bot**.

---

## Problem Statement

Build a RAG system (Python + ChromaDB + LangChain) over the Orient BlackSwan History catalogue PDF (~91 pages). It must:

1. Answer a question from the document with a reference to where the answer is (page number).
2. Reply **"Not found"** when the answer is not present in the document.

---

## Tech Stack

| Component | Choice |
|-----------|--------|
| PDF loading | `PyPDFLoader` (LangChain) |
| Chunking | `RecursiveCharacterTextSplitter` — 500 chars, 50 overlap |
| Embeddings | `sentence-transformers/all-MiniLM-L6-v2` (local, via `HuggingFaceEmbeddings`) |
| Vector store | Chroma (local, persisted to `./db`) |
| Retriever | Top-k=3 similarity search |
| LLM | `gemini-3.8-flash` (`ChatGoogleGenerativeAI`), temperature=0 |
| Orchestration | LangChain Expression Language (LCEL) |
| Backend API | FastAPI (`server.py`), CORS-enabled |
| Frontend | Single-file `index.html` (vanilla JS + Three.js background) |

> **Note on embeddings:** the project originally used Gemini's hosted embedding model, but switched to a local HuggingFace model after hitting the free-tier daily embedding quota (1,000 requests/day) partway through ingesting the ~1,397 chunks. Local embeddings removed the quota constraint entirely and run offline. The LLM (`gemini-3.8-flash`) is unaffected — chat completions and embeddings are separate quota pools on the Gemini API.

## Architecture / Flow

**Ingestion** *(offline, run once)*

```
PDF → PyPDFLoader (loads pages + metadata)
    → RecursiveCharacterTextSplitter (500 chars / 50 overlap)
    → HuggingFaceEmbeddings (all-MiniLM-L6-v2, local)
    → Chroma vector DB (./db)
```

**Query** *(runtime)*

```
User types a question in index.html
  → POST /ask to FastAPI server.py
  → Retriever does top-3 similarity search against Chroma ./db
  → Builds a prompt from context + question
  → Sent to Gemini 3.8 Flash (temperature=0)
  → If answer found in context → returns answer + cited page numbers
  → If not found → returns exactly "Not found"
  → Result shown back in the chat UI
```

The system prompt instructs the model to answer **only** from the retrieved context and to reply with exactly **Not found** if it is even slightly unsure — this is what keeps the assistant grounded and stops it from falling back on Gemini's general world knowledge (relevant for Q3 and Q4 below, which are deliberately outside the document's scope).

## Setup & Running

```bash
# 1. Install dependencies
pip install langchain langchain-community langchain-google-genai langchain-huggingface \
            chromadb pypdf python-dotenv sentence-transformers fastapi uvicorn

# 2. Add your Gemini API key
echo 'GOOGLE_API_KEY=your-key-here' > .env

# 3. Build the vector database (run once, or whenever the PDF changes)
python3 ingest.py

# 4a. Option A — terminal Q&A
python3 ask.py

# 4b. Option B — web UI
uvicorn server:app --reload          # starts API on localhost:8000
python3 -m http.server 3000          # serve the frontend
# then open http://localhost:3000
```

## Design Notes

- **Grounding enforcement:** a strict system prompt (*"answer ONLY from the context... if even slightly unsure, reply Not found"*) combined with `temperature=0` to minimize hallucination.
- **Citations are computed, not generated:** page numbers are read directly from the retrieved chunks' metadata (set by `PyPDFLoader` during ingestion), not asked of the LLM — this avoids the model inventing plausible-looking but incorrect page numbers.
- **Embedding/LLM split:** embeddings run entirely locally (no API quota, no cost, no key needed), while only the final answer generation step calls the Gemini API.
